## 🔧 Technical Implementation

### **New Backend Components**

**1. KMZ Generation Service** (`backend/kmzGenerator.js`)
- Parses KML/KMZ files using `jszip` and `fast-xml-parser`
- Extracts LineString coordinates from individual route files
- Merges multiple route segments into single combined path
- Applies color styling (Red: `ff0000ff`, Blue: `ffff0000` in KML ABGR format)
- Extracts source/destination points from locations template by name matching
- Bundles disclaimer KMZ into subfolder structure (`disclaimer/`)
- Handles missing files gracefully with skip reporting

**2. Storage Directories**
- `backend/templates/` - Stores uploaded locations.kmz and disclaimer.kmz
- `backend/temp/` - Temporary export files (auto-cleanup after download)

**3. API Endpoints**
- `POST /kmz_templates/upload` - Upload templates (Admin only)
- `GET /kmz_templates/info/:templateType` - Get template metadata
- `GET /kmz_templates/download/:templateType` - Download current template
- `POST /network_design/export_kmz` - Generate and download KMZ from design

**4. Database Migration**
- `backend/migrations/014_add_kmz_templates.js` - Creates `kmz_templates` table
- Smart migration detects and fixes incorrect schema automatically
- Table structure:
  ```sql
  CREATE TABLE kmz_templates (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    filename TEXT NOT NULL,
    uploaded_by INTEGER NOT NULL,
    uploaded_at TEXT NOT NULL,
    FOREIGN KEY (uploaded_by) REFERENCES users(id)
  )
  ```

### **🔴 CRITICAL: Protected Service Pricing Logic Overhaul** ⚠️

**BREAKING CHANGE - Protected Service Pricing Calculation:**

The protected service pricing logic has been completely rewritten to enforce margin targets and properly account for full redundancy costs.

**OLD Logic (Removed):**
- Primary path: 100%
- Secondary path: 70% (weighted by `protectionPathMultiplier`)
- Margins were informational, not enforced
- Formula: `Protected Price = Primary + (Secondary × 0.7)`

**NEW Logic (Enforced):**
- Primary path: 100%
- Secondary path: 100%
- **Margins are now ENFORCED** based on full allocated cost
- Formula: `Protected Allocated Cost = Primary Allocated + Secondary Allocated`
- Formula: `Protected Min Price = Allocated Cost / (1 - minMargin%)`
- Formula: `Protected Suggested Price = Allocated Cost / (1 - suggestedMargin%)`

**Key Changes:**

1. **Full Cost Recognition:**
   - Both primary and secondary allocated costs are included at 100%
   - Accurately reflects true cost of maintaining dual redundant paths

2. **Enforced Margin Targets:**
   - **12-month**: Min 50%, Suggested 70% (enforced)
   - **24-month**: Min 47.5%, Suggested 65% (enforced)
   - **36-month**: Min 45%, Suggested 60% (enforced)
   - Margins are calculated and guaranteed, not just informational

3. **Removed Configuration:**
   - `protectionPathMultiplier` (0.7) completely removed from:
     - Database (`pricing_logic_config` table)
     - Backend API (`GET/PUT /pricing_logic/config`)
     - Frontend UI (Pricing Logic Manager - "Additional Charges" section removed)
     - All default/seed configurations

4. **NRC Handling:**
   - Still charged once (from primary path only) - **NO CHANGE**

**Impact Example:**
```
Scenario: 12-month protected service
- Primary Allocated Cost: $600
- Secondary Allocated Cost: $800

OLD Calculation:
- Protected Allocated: $600 + ($800 × 0.7) = $1,160
- Protected Min (arbitrary): $2,000 (margin varies)

NEW Calculation:
- Protected Allocated: $600 + $800 = $1,400
- Protected Min (enforced 50%): $1,400 / 0.5 = $2,800 (exactly 50% margin)
- Protected Suggested (enforced 70%): $1,400 / 0.3 = $4,667 (exactly 70% margin)
```

**Why This Change:**
- ✅ Transparent, predictable pricing
- ✅ Margins always met (no guesswork)
- ✅ True cost of redundancy reflected
- ✅ Simplified configuration (less to maintain)

**Files Modified:**
- **Backend** (`backend/routes.js`):
  - Rewritten protected service pricing calculation (lines 5491-5598)
  - Removed `protectionPathMultiplier` from config endpoints
  - Updated default configurations
- **Frontend** (`frontend/src/PricingLogicManager.js`):

### **Live Latency - Staggered Bucket Refresh System** ⚡

**Performance Enhancement:**
- Completely redesigned automated live latency refresh to prevent "thundering herd" problem
- Previously: All 300+ circuits refreshed simultaneously every 15 minutes
- Now: Circuits divided into 4 buckets, refreshing 5 minutes apart

**New Architecture:**
- **Bucket System**: Circuits alphabetically sorted and split into 4 equal buckets
- **Refresh Frequency**: Each circuit still refreshes every **20 minutes** (5 minutes longer than before, but more reliable)
- **Staggered Timing**:
  - Bucket 0: Minutes 5, 25, 45... (~75 circuits)
  - Bucket 1: Minutes 10, 30, 50... (~75 circuits)
  - Bucket 2: Minutes 15, 35, 55... (~75 circuits)
  - Bucket 3: Minutes 20, 40, 60... (~75 circuits)
- **Startup**: Waits 5 minutes after server start before initiating staggered pattern

**Problem Solved:**
- ❌ **Before**: 300+ simultaneous API calls every 15 minutes
  - Overwhelmed external API endpoints
  - Application couldn't process all requests at once
  - Frequent failures and timeouts
- ✅ **After**: ~75 API calls every 5 minutes
  - Distributed load over time
  - API endpoints can handle smaller batches
  - Application processes each bucket smoothly
  - Reduced failure rate

**Automatic Scaling:**
- Bucket size automatically adjusts based on total circuits
- 300 circuits = 75 per bucket
- 400 circuits = 100 per bucket
- 500 circuits = 125 per bucket
- System remains stable up to ~800 circuits

**Technical Details:**
- Batch processing: Still 3 circuits at a time with 2-second delays (unchanged)
- Bucket assignment: Alphabetical sort ensures deterministic assignment
- Each bucket has independent interval timer (4 timers total)
- Latency warnings only updated after final bucket (Bucket 3) completes
- Processing time per bucket: ~50-90 seconds depending on circuit count

**Configuration:**
- Hardcoded: 4 buckets, 20-minute cycle, 5-minute offsets
- Suitable for up to 800 circuits without modification
- No database migration required

**Files Modified:**
- `backend/liveLatencyAutoRefreshService.js` (complete rewrite)

- Frontend constantly restarting

### **"Export button doesn't appear"**
- Ensure you have network_design module access
- Hard refresh browser
- Check console for errors

### **"Disclaimer template not found" error**
- Go to Admin → System Settings
- Upload disclaimer.kmz in KMZ Template Management section
- Template is required for all exports

### **"Some circuits were skipped"**
- Check that KMZ files exist for all circuits in the design
- KMZ files should be in `backend/kmz_files/` directory
- Filename format: `{circuit_id}.kmz` (e.g., `LONLON123456.kmz`)

### **"KMZ file won't open in Google Earth"**
- Verify file downloaded completely
- Check file extension is `.kmz`
- Try different KML viewer (Google Earth Pro, QGIS)
- Check backend logs for generation errors

### **Migration doesn't run**
- Ensure backend started successfully
- Check `migrations` table in database
- Review backend console output
- Delete migration entry from `migrations` table if needed to force re-run
