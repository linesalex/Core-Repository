#### 7. **Allocated Cost Calculator - Manual Incremental Costs** ✅
Added the ability to manually add incremental costs to pricing calculations in the Allocated Cost Calculator for scenarios requiring additional cost components beyond standard circuit costs.

**Cost Types:**
- **Core Incremental New** - A completely new network route segment being proposed between two locations
- **Core Incremental Upgrade** - Proposed increase in bandwidth or other element of an existing network route
- **Aggregate Cost A End** - Additional costs at the source location (e.g., POP-to-datacenter connectivity)
- **Aggregate Cost B End** - Additional costs at the destination location

**Features:**
- **Optional Accordion Section**: New "Manual Incremental Costs (Optional)" section between Design Parameters and Route Results
- **Table-Based UI**: Add/remove multiple costs with inline editing in a clean table format
- **Dynamic Field Rendering**: Fields change based on selected cost type
  - Core Incremental New: Autocomplete location selection from locations table
  - Core Incremental Upgrade: Select circuit from primary/secondary path routes (auto-fills source/destination)
  - Aggregate Costs: Free-form text entry for source/destination
- **Path Allocation**: Assign each cost to primary or secondary path
- **Currency Support**: Select from all available currencies with automatic conversion
- **Allocation Factor**: Specify percentage of cost to apply (0.0 to 1.0) for shared cost scenarios
- **Badge Counter**: Shows number of added costs in accordion header

**User Experience:**
- Click "Add Incremental Cost" to add a new cost row
- Select cost type from dropdown (4 options)
- Enter source and destination locations (field type varies by cost type)
- Enter incremental cost amount and select currency
- Specify allocation factor (e.g., 0.5 = 50% of cost applied)
- Choose path allocation (Primary or Secondary)
- For Core Incremental Upgrade: Select which circuit is being upgraded
- Delete cost rows with trash icon button
- Costs are cleared when form is refreshed

**Route Validation:**
- **For Core Incremental New**: System validates that existing circuits + new segments form a complete end-to-end path
- Uses BFS (Breadth-First Search) algorithm to verify path connectivity
- Supports multiple new segments chaining together
- Shows validation error if path is incomplete
- Allows calculation with ONLY new segments (no existing circuits required)
- **For Other Cost Types**: No route validation (documentation/audit trail only)

**Display in Results:**
- **Core Incremental New**: Displays as "New Core Circuit" with segment "Source → Destination", carrier "New", latency "New"
- **Core Incremental Upgrade**: Displays as "CIRCUIT123 (Upgrade)" with segment info
- **Aggregate Costs**: Displays as cost type name with "Source → Destination" segment
- **Light Green Highlighting**: All incremental cost rows highlighted in light green (#90EE90) in detailed calculations table
- **Allocation Factor Shown**: Displays allocation factor instead of utilization factor for incremental costs
- **"Without Utilization Factor" Table Display**:
  - Core Incremental New/Upgrade: Show with bandwidth-based allocation ratio (customer bandwidth / circuit bandwidth)
  - Aggregate Cost A/B End: Show at full cost value (100%) without allocation factor applied

**Calculation Logic:**
- Incremental costs converted to output currency using exchange rates
- **Main Allocated Cost Table**:
  - Core Incremental New/Upgrade: `Allocated Cost = Converted Cost × (Customer Bandwidth / Circuit Bandwidth) × Utilization Factor`
  - Aggregate Cost A/B End: `Allocated Cost = Converted Cost × Allocation Factor`
- **Without Utilization Factor Table**:
  - Core Incremental New/Upgrade: `Allocated Cost = Converted Cost × (Customer Bandwidth / Circuit Bandwidth)` (no utilization factor)
  - Aggregate Cost A/B End: `Allocated Cost = Converted Cost` (full cost, no allocation factor)
- Added to total allocated cost BEFORE margin calculations
- Separate addition to each path's allocated cost (primary/secondary)
- Protected pricing uses existing formula: `Primary + (Secondary × 0.7)`

**Validation Rules:**
- All fields required (Source, Destination, Cost, Currency, Allocation Factor, Path Allocation, Cost Type)
- Incremental Cost: Minimum 0, maximum 999,999,999
- Allocation Factor: Must be between 0.0 and 1.0 (inclusive)
- Core Incremental Upgrade: Circuit selection required
- Path validation: Existing + new segments must form complete path from source to destination

**Audit Trail:**
- Incremental costs saved in `allocated_cost_pricing_logs` table within `inputParameters.incrementalCosts`
- Historical pricing logs show all incremental costs used in calculation
- View Details displays full incremental cost data with all parameters

#### 8. **Customer Owned Crossconnect - Location Configuration** ✅
Added ability to mark locations where customers must provide their own cross connects, eliminating NRC/MRC charges while still enforcing cross connect visibility in the Design Tool.

**Purpose:**
Enable tracking of locations where CNX cannot provide cross connects but customer-provided cross connects are required for service activation.

**Features:**
- **New Checkbox in Location Manager**: "Customer Owned Crossconnect Only" option in cross connect configuration dialog
- **Mutually Exclusive Options**: Only one can be enabled at a time:
  - Enforce Mandatory Cross Connect (CNX provides and charges for cross connect)
  - Customer Owned Crossconnect Only (customer provides cross connect, no CNX charges)
  - Neither enabled = cross connect is optional
- **Greyed Out NRC/MRC Fields**: When customer-owned is enabled, NRC/MRC fields show "N/A - Customer Provided" and become disabled
- **Design Tool Integration**: Enforces cross connect display just like mandatory cross connect but shows "Customer must provide X/C" instead of pricing
- **Both Ends Support**: Works for A-end and B-end locations independently

**Location Manager Behavior:**
- Cross connect dialog has two checkboxes: "Enforce Mandatory Cross Connect" and "Customer Owned Crossconnect Only"
- Checking one automatically unchecks the other (mutual exclusivity enforced in UI and backend)
- When customer-owned is enabled:
  - NRC Amount field shows placeholder "N/A - Customer Provided" and is disabled
  - MRC Amount field shows placeholder "N/A - Customer Provided" and is disabled
  - Currency dropdowns are also disabled
  - Cross connect notes field remains editable for documentation
- Default state: neither option enabled (cross connect is optional)

**Design & Pricing Tool Behavior:**
- Locations with customer-owned cross connect auto-enable cross connect display (like mandatory)
- Cross connect card shows "(Customer Owned)" label in header
- NRC displays as "Customer must provide X/C" instead of price
- MRC displays as "Customer must provide X/C" instead of price
- Cannot be disabled by user (enforced like mandatory cross connect)
- Export emails show "(Customer Owned)" label and "Customer must provide X/C" text
- Currency line is not shown in emails for customer-owned cross connects
