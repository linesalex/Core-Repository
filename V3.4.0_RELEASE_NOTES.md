**Release Date:** November 19, 2024

## 🎉 What's New in v3.4.0

### **Bandwidth-Based Margin Pricing** 💰 - NEW MAJOR FEATURE

Implement dynamic margin scaling based on bandwidth tiers. Lower bandwidth requests now have higher margins, while higher bandwidth requests have lower margins. This brings pricing logic in line with industry best practices where margin requirements decrease as bandwidth increases.

---

## 🚀 Key Features

### **Four-Tier Bandwidth System**
- ✅ **Under 100 Mb** - Highest margin tier for small bandwidth requests
- ✅ **100 to 999 Mb** - Medium-high margin tier
- ✅ **1000 to 2999 Mb** - Medium-low margin tier  
- ✅ **3000 Mb Plus** - Lowest margin tier for large bandwidth requests

### **Independent Margin Configuration**
- ✅ **Standard Service Margins** - Separate min/suggested margins for each bandwidth tier (12-month contracts)
- ✅ **Protected Service Margins** - Separate min/suggested margins for each bandwidth tier (12-month contracts)
- ✅ **Contract Term Discounts** - 24-month and 36-month contracts now use discount percentages off 12-month pricing
- ✅ **Backward Compatibility** - Automatic migration preserves existing pricing behavior

### **Enhanced Contract Term Logic**
- ✅ **12-Month Contracts** - Bandwidth-tiered margins apply directly
- ✅ **24-Month Contracts** - Configurable discount percentage (default: 5%) applied to 12-month prices  
- ✅ **36-Month Contracts** - Configurable discount percentage (default: 10%) applied to 12-month prices
- ✅ **NRC Charges** - Remain separate for each contract term as before

### **Preserved Promo Pricing Logic**
- ✅ **Promo Pricing Takes Precedence** - Existing promo pricing still checked first
- ✅ **Flat 35% Minimum Margin** - Promo pricing continues to use absolute 35% floor
- ✅ **Bandwidth-Tiered Fallback** - Regular pricing uses bandwidth-based margins when promo doesn't meet minimum

## 📋 How to Use

### **Admin Configuration**
1. Navigate to **CNX Eth Design & Pricing Tool → Pricing Logic**
2. Configure **Base Service Margins (12-Month Contract)**:
   - Set separate min/suggested margins for each of 4 bandwidth tiers
3. Configure **Contract Term Discounts & NRC Charges**:
   - Set discount percentages for 24-month and 36-month contracts

4. Configure **Protected Service Margins (12-Month Contract)**:
   - Set separate min/suggested margins for each bandwidth tier
   - Set discount percentages for 24-month and 36-month protected contracts

## 🔧 Technical Implementation

### **New Backend Components**

**1. Bandwidth Tier Helper Function** (`backend/routes.js`)
- `getBandwidthTier(bandwidth)` - Determines which tier a bandwidth falls into
- Returns: `under_100mb`, `from_100_to_999mb`, `from_1000_to_2999mb`, or `over_3000mb`
- Used in all pricing calculations to select appropriate margins

**2. Updated Pricing Logic Configuration**
- `getPricingLogicConfig()` - Enhanced to include bandwidth tiers
- Default structure:
  ```javascript
  contractTerms: {
    12: {
      bandwidthTiers: {
        under_100mb: { minMargin: 50, suggestedMargin: 60 },
        from_100_to_999mb: { minMargin: 40, suggestedMargin: 50 },
        from_1000_to_2999mb: { minMargin: 35, suggestedMargin: 45 },
        over_3000mb: { minMargin: 30, suggestedMargin: 40 }
      },
      nrcCharge: 1000
    },
    24: {
      discountPercent: 5,
      nrcCharge: 500
    },
    36: {
      discountPercent: 10,
      nrcCharge: 0
    }
  }
  ```

**3. Updated Pricing Calculation Logic** (`backend/routes.js`)
- `calculatePathPricing()` - Modified to:
  - Determine bandwidth tier for request
  - Fetch tier-specific margins from configuration
  - Apply discount percentage for 24-month and 36-month contracts
  - Calculate prices based on tier margins
  - Apply contract term discounts to final prices

**4. Updated Protected Service Pricing**
- Protected service margins now use same bandwidth tier system
- Separate tier configurations for protected services
- 24-month and 36-month discounts apply to final protected prices

**5. Database Migration**
- `backend/migrations/015_add_bandwidth_based_margins.js` - Creates/updates pricing configuration
- Populates bandwidth tiers with existing flat margins (backward compatibility)
- Sets default discount percentages for 24-month (5%) and 36-month (10%) contracts
- Safe to run multiple times (idempotent)

### **New Frontend Components**

### **Database Migration**

**Migration `017_add_sales_permission_level.js`**:
- ✅ Updates `user_module_permissions` table CHECK constraint
- ✅ Adds 'sales' as valid permission level alongside 'read_only' and 'provisioner'
- ✅ Recreates table structure while preserving all existing data
- ✅ Automatically runs on backend startup
- ✅ Safe to run multiple times (idempotent)
- ✅ Transaction-based (rolls back on any error)

**Why This Migration?**
The existing `user_module_permissions` table had a CHECK constraint: `permission_level IN ('read_only', 'provisioner')`. This prevented inserting 'sales' permissions. The migration recreates the table with an updated constraint: `permission_level IN ('sales', 'read_only', 'provisioner')`.

## 🎯 Pricing Logic Flow

### **Standard Service Pricing (Example: 50 Mbps, 12-Month)**

```javascript
1. Request: 50 Mbps bandwidth
2. Determine tier: getBandwidthTier(50) → "under_100mb"
3. Fetch margins: config.contractTerms[12].bandwidthTiers.under_100mb
   → minMargin: 50%, suggestedMargin: 60%
4. Calculate allocated cost: $800 (from routes)
5. Apply margin:
   → Min price: $800 / (1 - 0.50) = $1,600
   → Suggested price: $800 / (1 - 0.60) = $2,000
6. NRC: $1,000 (from config.contractTerms[12].nrcCharge)
```

### **24-Month Contract Discount (Example: 50 Mbps, 24-Month)**

```javascript
1. Calculate 12-month price: $2,000 (suggested)
2. Fetch discount: config.contractTerms[24].discountPercent → 5%
3. Apply discount: $2,000 × (1 - 0.05) = $1,900
4. NRC: $500 (from config.contractTerms[24].nrcCharge)
```

### **Protected Service Pricing (Example: 50 Mbps Protected, 12-Month)**

```javascript
1. Primary allocated: $800, Secondary allocated: $600
2. Total allocated: $1,400
3. Determine tier: getBandwidthTier(50) → "under_100mb"
4. Fetch protected margins: config.protectedServiceMargins[12].bandwidthTiers.under_100mb
   → minMargin: 60%, suggestedMargin: 70%
5. Apply margin:
   → Min price: $1,400 / (1 - 0.60) = $3,500
   → Suggested price: $1,400 / (1 - 0.70) = $4,667
6. NRC: $1,000 (from primary path)
```

## ⚠️ Important Notes

### **Migration Behavior**
- **Automatic migration** runs on backend startup
- **Backward compatibility**: Existing 12-month margins copied to ALL bandwidth tiers
- **Default discounts**: 5% for 24-month, 10% for 36-month contracts
- Safe to run multiple times (idempotent)
- No data loss - only adds new configuration structure

### **Promo Pricing Precedence**
- Promo pricing **ALWAYS checked first**
- If promo price meets **35% minimum margin**, it is used
- If promo price doesn't meet minimum, **bandwidth-based pricing is used**
- This ensures promo pricing remains effective while maintaining floor margins

### **Suggested vs. Minimum Margins**
- **Minimum margins**: Absolute floor - prices cannot go below this
- **Suggested margins**: Recommended target for standard quotes
- Admins can adjust both independently for each bandwidth tier

### **Dark Fiber Handling**
- Dark Fiber treated as **200,000 Mbps** for allocated cost calculations
- Not possible to request as a service design (infrastructure only)
- Falls into "3000 Mb Plus" tier for any margin calculations

## 📞 Support & Troubleshooting

### **"Bandwidth tiers not showing in Pricing Logic Manager"**
- Hard refresh browser: `Ctrl + Shift + R`
- Clear browser cache
- Check console for errors
- Verify migration ran successfully in backend logs

### **"Pricing calculations seem wrong"**
- Verify bandwidth tier thresholds:
  - < 100 Mbps → "Under 100 Mb"
  - 100-999 Mbps → "100 to 999 Mb"
  - 1000-2999 Mbps → "1000 to 2999 Mb"
  - ≥ 3000 Mbps → "3000 Mb Plus"
- Check configured margins for each tier
- Verify promo pricing isn't overriding (check for "PROMO PRICING APPLIED" badge)

### **"Can't save configuration changes"**
- Ensure you are logged in as administrator
- Check for validation errors on margin inputs
- Verify backend is running and accessible
- Check browser console for API errors

### **"Migration fails to run"**
- Check backend logs for error details
- Verify database is accessible
- Check that `migrations` table exists
- Delete migration entry if needed to force re-run:
  ```sql
  DELETE FROM migrations WHERE name = '015_add_bandwidth_based_margins.js';
  ```

### **"Existing designs showing different prices"**
- This is expected - new margin structure may change calculations
- Saved logs preserve original pricing at time of quote
- New calculations use current bandwidth-based configuration
- Review and approve any significant pricing changes
